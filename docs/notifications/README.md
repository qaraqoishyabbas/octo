# Уведомления Octo

Laravel API хранит приложения, credentials провайдеров, push-токены пользователей и историю доставок. Новое сообщение автоматически создаёт доставку для адресатов с зарегистрированными токенами. Веб-клиент получает push через отдельный service worker и управляет настройками в «Уведомления и звук».

## Запуск

1. В `apps/api` выполните `composer install` и `php artisan migrate`.
2. Запустите очередь: `php artisan queue:work --tries=3`. Для разработки допустим `QUEUE_CONNECTION=sync`; в рабочей среде используйте постоянный queue worker.
3. Откройте в Laravel-админке раздел **Уведомления** (`/notification-apps`), нажмите **Добавить приложение**, выберите платформу и сохраните credentials через кнопку **Credentials**. Те же операции доступны через REST API. Для Android используйте FCM HTTP v1, для iOS — APNs token authentication или FCM. `desktopapp` в первой версии использует Web Push (например, Electron/Tauri с поддержкой Push API).
4. Скопируйте ID web-приложения из таблицы админки. В `apps/web/.env` укажите `NUXT_PUBLIC_NOTIFICATION_APP_ID=<UUID web-приложения>` и пересоберите Nuxt.
5. Откройте настройки веб-клиента и нажмите «Включить уведомления». До включения окно показывает только приглашение; остальные настройки появляются после регистрации подписки. Нужен HTTPS или `localhost`, а разрешение запрашивается после нажатия кнопки.

Для Web Push откройте в админке **Уведомления → Credentials → WEBPUSH** и нажмите **Сгенерировать VAPID-ключи**. Сервер вызовет `VAPID::createVapidKeys()` и заполнит поля **Public key** и **Private key**. В **VAPID subject** укажите контактный адрес, например `mailto:admin@example.com` (используйте свой реальный email), затем нажмите **Сохранить**. Генерация сама по себе не меняет сохранённые credentials; ключи сохраняются зашифрованными только после отправки формы.

Приватный ключ не помещайте в Nuxt или клиентское приложение. При замене существующих VAPID-ключей пользователям потребуется заново включить уведомления. Для frontend нужен UUID web-приложения из таблицы админки, а не приватный ключ.

## Поведение чатов

- Автор сообщения push не получает.
- Mute диалога подавляет push без упоминания. Push с упоминанием поступает в браузер, где локальная настройка «Упоминания в заглушённых чатах» решает, показывать его или нет.
- После включения Web Push переключатели «Уведомления», «Звук», «Счётчик на значке», «Показывать текст», «Имена в уведомлениях» и «Упоминания в заглушённых чатах» сохраняются только в этом браузере. Запросы настроек к Laravel не выполняются. Service worker читает их копию из Cache Storage при получении push.
- «Сбросить настройки уведомлений» возвращает локальные значения по умолчанию. «Отключить уведомления в этом браузере» удаляет push-подписку и зарегистрированный на сервере токен.
- Флаг `silent: true` при отправке сообщения выключает звук независимо от локальной настройки. В интерфейсе чата для этого есть кнопка колокольчика рядом с отправкой.
- Badge берётся из числа непрочитанных сообщений, если локальная настройка включена. Веб-клиент также обновляет значок приложения при изменении списка диалогов.
- Веб-клиент не показывает push-уведомление, когда его окно видно на экране. При открытии диалога он закрывает все ранее доставленные браузерные уведомления этого диалога; уведомления других диалогов остаются.

`sent` в журнале означает приём запроса push-провайдером, а не подтверждение просмотра на устройстве. Недействительные токены удаляются при ответе провайдера; другие сбои проходят через повторы очереди и фиксируются как `failed`.
