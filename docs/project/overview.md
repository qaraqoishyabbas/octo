# Octo — описание проекта и анализ состояния

Дата: 12 октября 2026. Основание: локальный код на `13fad8a`, маршруты, модели, миграции, тесты и существующая документация. Цель roadmap подтверждена пользователем: **стабильный первый релиз**.

## Назначение

Octo объединяет личную переписку, общение в группах и публикации в каналах в адаптивном веб-приложении. Пользователь входит по username и паролю, находит людей и диалоги, отправляет текст и вложения, получает обновления без перезагрузки и управляет настройками своего устройства.

Первый релиз предлагается проводить как закрытый пилот с аккаунтами, созданными администратором. Это соответствует текущему способу создания пользователей; масштаб пилота и аудитория пока не согласованы. Открытая регистрация, восстановление доступа и массовое привлечение потребуют отдельного решения.

Основная ценность первого релиза — предсказуемое общение: сообщение сохраняется один раз, история восстанавливается после обрыва сети, приватные данные доступны по правам, а интерфейс объясняет состояние операции.

## Участники и сценарии

| Участник | Основные действия |
| --- | --- |
| Пользователь | Вход, переписка, поиск, вложения, архив, настройка уведомлений, отзыв сессий |
| Владелец/администратор диалога | Управление участниками, правами, профилем и приглашениями |
| Администратор платформы — предлагаемая отдельная роль | Создание аккаунтов, управление платформой и notification-приложениями |
| Оператор развёртывания | Настройка окружения, backup, восстановление, наблюдение за API/Reverb/очередью |

Роли `owner/admin/member` уже существуют внутри диалогов. Они не дают отдельной защиты административной панели платформы.

## Реализованные возможности

«Реализовано» здесь означает наличие связанного кода и, где указано, автоматических проверок. Это не статус приёмки в реальном браузере или на сервере.

| Область | Текущее состояние | Основание / граница |
| --- | --- | --- |
| Вход и устройства | Sanctum Bearer-токены, срок день/месяц, список устройств и отзыв токенов | `AuthController`, `DeviceController`, `TokenAuthTest`; публичного registration API нет |
| Диалоги | Личные, группы, каналы, приглашения, роли и permissions | `DialogController`, `DialogAccess`, `DialogResource` |
| Сообщения | Текст, ответ, изменение, удаление, закрепление, тихая отправка | `MessageController`; есть feature-тесты основных операций |
| История | Курсорная пагинация, загрузка вокруг сообщения, управление прокруткой | `MessageCursorTest`, stores/messages, composables/useMessageList* |
| Непрочитанные | Счётчики, отметка чтения, упоминания | `DialogUnreadMessagesTest`, dialogs/messages stores |
| Поиск | Пользователи, диалоги, сообщения внутри выбранного диалога | `MessageController::search` использует SQL `LIKE`; глобальный поиск и расширенные фильтры не подтверждены |
| Вложения | Временная загрузка, прогресс, отмена, повтор, превью, скачивание, ссылки | Upload/Attachment controllers и stores/uploads; медиа на public disk |
| Realtime | Новые/изменённые/удалённые/закреплённые сообщения, membership, typing, presence | Reverb, `DialogRealtime`, websocket plugin/store |
| Push | Web Push, FCM, APNs, журнал доставок, queue jobs | `PushProvider`, `NotificationServiceTest`; реальная внешняя доставка в этом анализе не проверялась |
| Архив и папки | Серверный архив, выбор вкладок-фильтров локально для пользователя | `chat-folders.ts`; произвольные серверные папки не реализованы |
| Персонализация | Темы, радиус, обои, языки ru/kk/en, emoji-панель | app.config, theme assets, nuxt.config; наличие языковых файлов не означает полноту перевода |
| Данные устройства | Автозагрузка медиа, оценка кэша и трафика, очистка | media-auto-download/storage-usage/network-usage stores; показатели трафика не являются серверным биллингом |
| Черновики | Локальные, привязаны к пользователю и диалогу | `messages-draft.ts`; серверной синхронизации нет |
| Встречи | WebRTC, микрофон/камера, screen share, участники, reconnect | `pages/calls/room/[username].vue`; только STUN, вход по непустому имени комнаты для любого вошедшего пользователя |
| Админка | Пользователи, группы/каналы, notification-приложения | `routes/web.php`; маршруты защищены `auth`, отдельного admin gate нет |

Enum содержит тип `B` для ботов. Это не свидетельствует о готовом bot API. Неиспользуемые пункты «Магазин», «Опросы» и «Помощь» удалены из меню сервисов.

## Оценка состояния

Проект уже вышел за рамки прототипа экрана переписки: есть существенная доменная логика, единые frontend stores, проверки конкурентных запросов и развитая работа с историей. Backend — единое Laravel-приложение, frontend — SPA с локальными механизмами кэширования и PWA.

Основной пробел перед первым релизом — согласованная граница безопасности и надёжности между HTTP, WebSocket, файлами и browser cache. Добавление новых коммуникационных функций сейчас увеличит число сценариев, которые ещё нужно принимать.

## Риски и подтверждения

| ID | Наблюдение | Значение для релиза | Источник |
| --- | --- | --- | --- |
| A1 | Админка проверяет вход, но не отдельную роль | Обычный аккаунт может пройти административную авторизацию; требуется platform admin gate | `routes/web.php`, Admin/AuthController, Models/User |
| A2 | Медиа перемещаются в `Storage::disk('public')`, настроен `/storage` | Защищённый download API не защищает прямую выдачу того же файла по известному URL | MessageController, MessageAttachmentController, config/filesystems.php |
| A3 | Workbox кэширует `/api/v1/*` в общий `api-cache`; auth reset не очищает этот кэш | Нужна проверка изоляции аккаунтов и поведения офлайн; утечка в браузере здесь не воспроизводилась | nuxt.config.ts, stores/auth.ts, utils/storage-usage.ts |
| A4 | Создание сообщения не принимает idempotency key | Повтор после потерянного ответа может создать второе сообщение | `MessageController::store`, валидатор запроса |
| A5 | Broadcast синхронный, ошибки перехватываются; при reconnect обновляется список диалогов | Нельзя считать WebSocket журналом доставки; восстановление полной открытой истории требует отдельной проверки/механизма | DialogRealtime, DialogRealtimeEvent, plugins/websocket.client.ts |
| A6 | Перемещение файлов происходит внутри DB transaction | Откат БД не откатывает файловую систему; требуется обработка частичных ошибок | `MessageController::store` |
| A7 | Один frontend-тест не проходит | Есть конфликт текущей разметки с правилом независимых интерактивных контролов | notification-settings-buttons.test.ts, SettingNotifications.vue |
| A8 | Встречи используют STUN и общую авторизацию комнаты | Надёжность через сложные сети и приватность встреч ещё не подтверждены | call room page, routes/channels.php |

Это не полный аудит безопасности. Поведение production, фактические origin, доступность конкретных файлов, восстановление backup и реальная доставка push не проверялись.

## Проверки 12 октября 2026

Среда: Node `26.5.0`, PHP `8.4.1`. Версии зависимостей в документах берутся из manifest-файлов как объявленные диапазоны, а не как сверенные версии всех установленных пакетов.

| Команда | Результат |
| --- | --- |
| `cd apps/api && php vendor/bin/phpunit` | **177/177**, 802 assertions; полный повторный запуск с разрешённым localhost |
| `cd apps/web && node --test test/*.ts` | **264/265**; падает `switch controls are not nested inside buttons` |
| `cd apps/web && npm run build` | Успешно; есть предупреждения sourcemap/зависимостей, сборка не является typecheck или browser QA |

Первый backend-запуск в sandbox дал 174 успешных теста и 3 ошибки в `DevelopmentMediaCorsTest`: `stream_socket_server` запрещён средой. Эти три теста отдельно, затем полный набор прошли при разрешённом localhost. Ошибка среды не включается в backlog продукта.

Frontend-падение подтверждается исходником: `USwitch` находится внутри `UButton`. Тест анализирует текст компонента; double-toggle и поведение клавиатуры в браузере в этом запуске не проверялись. Задача релиза — определить корректное взаимодействие и согласовать с ним DOM и тест.

В репозитории найдены 46 frontend test-файлов и 34 backend-файла в `tests`, включая инфраструктурный `TestCase`. Проверки часто используют моки и анализ исходников; они не заменяют сквозные проверки в браузере. В корне не обнаружен `.github` с CI workflow. Сборка админки, `nuxt generate`, production smoke, нагрузка и визуальная приёмка не запускались.

## Что меняется в планировании

В исходном состоянии [Roadmap.vue](../../apps/web/app/components/feature/roadmap/Roadmap.vue) смешивал реализованные функции с будущими расширениями. Поиск помечен done, хотя описание включает глобальный поиск и фильтры; встречи помечены done без оговорок о TURN и модели доступа; emoji объединены с отсутствующими стикерами и GIF; папки описаны шире текущего локального выбора фильтров.

Новый [roadmap](roadmap.md) использует результат и критерии приёмки, а не только факт наличия компонента. Его задачи пока имеют статус «запланировано»: существующая реализация — baseline, а не выполненные этапы нового релиза. Экран roadmap обновлён: теперь показывает этапы R0–R3, приоритеты, критерии готовности и задачи после первого релиза. При разработке нужно поддерживать его согласованность с документом.
